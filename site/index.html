MASS

The orchestrator for self-hosted AI inference

One hub for your AI fleet: MASS stores your models, installs pluggable runtimes, and schedules work across your machines — any model format, any API, one dashboard.

Download MASS Quickstart
llama.cpp today — vLLM, TTS, diffusion next

One coordinator, pluggable edges

MASS coordinates

Durable job queues, latency-aware placement, streamed results, an operator dashboard. It routes bytes it never interprets.

Gateways translate

Installable .mass packages teach MASS a runtime: its model formats, its API (OpenAI-compatible or typed), its job payloads.

Workers execute

Native binaries hold models resident on your GPUs (Vulkan, Metal) and join the fleet over one gRPC stream.

Features

Pure-Go core

Inference toolchains stay in the workers. One static server binary.

Daemon plus thin clients

The hub is a daemon the window only attaches to. Run mass serve and the fleet stays up, dashboard open or not.

Live runtime installs

Install, start, stop gateway packages from the dashboard. No rebuilds.

One model store

Import from Hugging Face or disk. Workers pull what they run, deletes propagate.

Latency-aware scheduling

Placement by predicted wall-clock cost. Streams survive reconnects.

Fleet control

Enable workers and devices individually. Every model is measured on every worker before a job lands there.

Downloads

On macOS and Linux, one line fetches the installer and runs the wizard:

$ curl -fsSL https://raw.githubusercontent.com/chinese-room-solutions/mass/main/install.sh | sh

Or download the installer for your platform:

All releases, checksums, and older versions live on the GitHub releases pages.

Quickstart

# 1 — install MASS on your main machine: one line fetches the installer and runs the wizard
#     (or grab the .AppImage from Downloads above and double-click it in your file manager)
$ curl -fsSL https://raw.githubusercontent.com/chinese-room-solutions/mass/main/install.sh | sh

# 2 — in a new terminal: confirm the hub is up — dashboard at :3455
$ mass status

# 3 — install the llama.cpp runtime; it starts on install (or do it from the dashboard)
$ mass runtimes install mass-runtime-gateway-llama-cpp

# 4 — add a worker on this machine — or print the commands to paste on each GPU machine
$ mass workers install-local
$ mass workers join-command

# 5 — watch the fleet come up
$ mass workers list

# 6 — import a model into MASS — workers fetch what they run from the hub's store.
#     The import returns at once and downloads in the background; list shows the model id
$ mass models import-remote --runtime llama-cpp --repo ggml-org/Qwen3.5-0.8B-GGUF --file Qwen3.5-0.8B-Q4_0.gguf
$ mass models list

# 7 — inference, OpenAI-style, through MASS
$ curl -X POST http://localhost:3455/mass.llama-cpp/v1/chat/completions -d '{"model":"cli/Qwen3.5-0.8B-Q4_0.gguf","messages":[{"role":"user","content":"hi"}]}'

The mass binary is also the CLI for the whole mass.v1 API — a verb starts the daemon on demand, so the first command works on a fresh install. It carries a CLI skill that teaches coding agents the verbs (mass skill install DIR), and the same API speaks gRPC and plain HTTP/JSON.

Ecosystem

Runtime stack — llama.cpp

A runtime comes in two halves: the gateway package MASS installs, and the worker binary your GPU machines run.

llama.cpp runtime

The .mass gateway package that teaches MASS the llama.cpp ecosystem: model formats, APIs, job payloads.

llama.cpp worker

The native binary that holds models resident on your GPUs and executes the jobs. Installable on Linux and Windows (Vulkan) and macOS Apple Silicon (Metal).

Libraries

The building blocks — use them to write your own runtime, worker, or client.

Contracts & SDK

mass-proto — the gRPC contracts every component speaks. mass-sdk — shared Go toolkit: UI kit, themes, installers.

Go clients

OpenAI-compatible and typed gRPC clients for llama.cpp servers.
